# Codex 插件内容同步与恢复验收设计

日期：2026-10-03。基线：U同步 2.2.2 / `25b68d714317733482784cbc43c2c498d624801c`。本稿描述本次授权的优化；实现和安装结果另记，不将设计当作已完成。

## 用户目标与范围

用户希望在两台电脑间同步 Codex 插件，包含本地定制，并确认目标机实际安装、启停及宿主加载。此次明确授权详细研究、设计、实施及提交推送。沿用已有 export → import/pull → setup → verify 链路；不增加独立 Skill 或同步服务，不改变设备身份、个人记忆和项目文件传输职责。

本次软件验收包括真实 Codex CLI 安装及 app-server Skill 发现。惠普当前环境不在本机可操作范围，软件验收不能写成惠普办公环境已完成迁移。历史会话、登录、宿主信任、活动数据库及无关插件不恢复。

## 调查结果

- `src/lib/state.ts` 的 readCodexState 从 TOML 获得插件条目，把市场 last_revision 当作 version，所有 source_type=local 都标记为 codex-runtime。scanInstalledCodexExtensions 重读配置，未取得真实安装证据。
- `src/lib/recovery-manifest.ts` 的标识只有 kind:id，同名不同市场可能互相覆盖。
- `src/lib/codex-restore.ts` 注册市场并执行 plugin add；命令成功/已经存在即可写 restored。Skill 恢复有清单回扫，但插件没有对应验收。
- setup 已是扩展恢复的统一入口；verify 只检查 U同步插件及选定 Skill/MCP，未逐插件核验。
- Codex CLI 0.157.0：plugin add 没有版本参数；marketplace add 同名不同来源拒绝。隔离实测使用命令级 `-c marketplaces.<name>.source_type="local"` 和 source 覆盖安装 1.0.2，原永久市场仍指向1.0.1来源，完整 selector 不变；新 app-server 的 skills/list 返回1.0.2缓存中的 Skill。新设备必须保留一个可解析市场，不能只留下暂时配置覆盖。
- 官方资料：https://developers.openai.com/plugins/build/plugins 。本地市场和安装缓存是不同对象；插件 Hook 需要用户信任，安装不会自动赋予信任。

GitNexus 的 readCodexState 上游影响为 HIGH（2个直接调用方，导出/setup/CLI流程）；restoreCodexExtensions、classifyExtensions、exportSystemState 上游为 LOW。索引比当前源码旧且FTS不可用，实际源码/测试审查补充覆盖，不将索引视为完整证据。

## 选择与边界

选择在已有插件恢复模块增加内部内容快照与验收辅助文件。保留既有 `agents.codex.plugins` 清单和 ExtensionRef；新增可选字段，兼容旧artifact。不开平行设备表，不更换插件标识，不批量替换用户市场，也不凭本地目录推定官方或宿主管理来源。

其他可选方式：只安装市场最新版本无法保证内容一致；复制全部 `.codex` 会夹带登录/信任/运行状态；另建新市场标识可能产生重复插件。当前选择固定插件内容，并通过官方安装器的命令级源覆盖安装；原有市场已存在时保持其配置，新目标仅注册缺失市场。

插件完整身份为 `<id>@<marketplace>`。无法取得 marketplace 的旧条目仅可在唯一匹配时处理；同名歧义拒绝，不静默去重。永久删除记录仍按现行协议阻断安装，同名多市场删除须明确报告影响。

## 内容与证据契约

真实清单来自 `codex plugin list --json`（显式目标 CODEX_HOME）。保存实际 pluginId、manifest version、enabled、市场来源类型和来源引用；本机绝对路径仅用于读取，不作为跨机安装地址。CLI不可用、清单损坏或只有配置没有安装证据时报告未验证，不将回退配置冒充安装事实。

有本地可读包的已安装插件保存安装缓存内容快照；可定位的源目录不同且含定制时另保存源内容，恢复时保留在受控源归档，不能把未安装源码冒充当前运行内容。宿主管理、远程托管或来源不可读取的项记录明确限制，继续逐项检查实际状态，不冒充有内容快照。

独立源码因凭据、不可访问、manifest 缺失、损坏或身份不匹配而无法归档时，保留已经通过校验的安装内容，在 remaining 中记录缺口，导出标记 partial。该降级不允许绕过安装内容自身的安全或一致性检查，也不宣称源码定制已经备份。

快照是 ExtensionRef 的可选 pluginSnapshot，schemaVersion=1，包含 selector、实际版本、文件相对路径/字节/摘要、整体摘要及组件信息；市场原来源身份在 ExtensionRef.source 保留。安装缓存和源码运行绝对路径不写入 config。内容受确定总量/文件上限限制，校验 UTF-8文本及少量已识别静态图片格式，路径、图片扩展与文件头一致性、凭据文件和文本密钥检查仍适用。未知/敏感内容拒绝并保留原文，不绕过既有秘密检查。Git内部、node_modules和可再生Python缓存不作为迁移内容；依赖锁及构建产物保留，依赖通过锁文件在目标受控目录重建，不运行用户安装脚本。排除项必须可见。

所有输入均在写入前校验：对象结构、文件数/总量、路径、大小、摘要、manifest name/version、重复路径、大小写碰撞、链接/特殊文件、源和目标分离。绝不沿链接逃出插件根，也不接受快照提供的命令、允许名单或绝对写入路径。安全扫描是启发式证据，不宣称绝对无秘密。

Python 和 JavaScript/TypeScript 源码使用固定解析器区分变量引用、生成器调用与字面量，避免将 secrets.token_hex(8) 等生成器调用误判为内联凭据。字符串、模板文字、注释、正则字面量和调用参数继续扫描；已知令牌前缀始终检查原文，语法错误关闭豁免。字段名和三元表达式的文字边界由语法确认，不把文字末尾的词与外部运算符拼成赋值。Python 空 yield 仅接受解析器产生的零宽缺少操作数节点且父节点原文恰为 yield，不改写原文件，也不放行其他语法错误。

## 恢复与冲突保护

2026-10-07 校验修复：文件的 Base64 表示先检查长度、四字节对齐与字符，再有界解码并比较规范编码；拒绝无效填充和非零填充位。避免重复分组正则在合法大文件上耗尽调用栈。8MiB 单文件、32MiB 总量、原有二进制与凭据检查继续适用；该修复不扩大备份内容范围。

1. 读取清单、删除标记与目标真实清单。校验全部拟安装快照，识别完整selector和来源冲突。已有同selector来源不同或同版本内容被本地改动时停止该项，保留双方内容；不自动删除、强制覆盖或恢复已停用插件。
2. 将经过验证的固定内容展开到工具拥有的目标目录，生成使用原 marketplace 名和插件名的本地catalog。目录不可变，摘要重复可复用；内容不同不覆盖。目标备份及结果回执在目标Codex的U同步状态目录，不写公共源码仓库。
3. 原市场存在时保留其配置，用命令级覆盖执行 `codex plugin add <selector> --json`；没有市场时注册受控catalog。安装前保护可能被替换的同版本缓存和配置，目标变更遇已知冲突拒绝。命令退出成功只代表命令成功。
4. 按源机明确的enabled状态恢复该项，保留其他插件配置及宿主信任。禁用项仍可安装并保持禁用，不能以启用命令实现禁用恢复。
5. 新进程回扫安装版本、enabled和完整selector；检查安装缓存实际文件摘要。Source列表可能仍指向原永久市场，内容证据必须来自真实安装目录/宿主Skill路径，不使用源路径替代缓存验收。
6. 以无模型请求的 app-server initialize → skills/list 验证启用插件的预期Skill路径、pluginId、enabled和加载错误。只检查选定项，不因无关用户Skill警告判目标成功或失败。禁止自动运行Hook、修改trust或执行快照提供的健康命令。
7. 结果逐项保留命令/安装/内容/启停/Skill发现证据。Hook信任、MCP认证和任意业务流程属于独立运行验收，未检查/需要用户动作明确报告。不得把Skill发现等同任意插件业务成功。旧清单没有版本/内容时只能获得相应较弱证据，不补造固定内容保证。

标记为 codex-runtime 的宿主管理插件仅做新鲜的只读核验，不注册市场、不调用安装器、不修改启用状态或写接受基线。缺失、版本/启停不符仍是验收失败，并提示需由 Codex 宿主处理，不能以跳过执行冒充恢复成功。

跨版本升级不要求把旧缓存变成可上传快照：旧版本可能含有被导出扫描拒绝的本地内容，不能因此阻止安装已通过完整检查的新版本。安装前做仅留本机的回退源码副本，拒绝链接、硬链接、特殊文件和超限目录，以独占写入保留原始字节，不写入 portable snapshot、catalog 或公开仓库。Codex 安装器可能清理旧版本缓存，不能承诺旧目录原地保留；回退以备份副本为准。依赖及可再生缓存不复制，必要时通过备份中的锁文件重建；无锁文件的旧运行依赖不能据此保证可重建。此副本不是安全导出结果，后续 export 仍执行完整凭据检查。若跨版本目标目录已存在，即使未被宿主登记也拒绝覆盖；同版本升级仍须匹配已验收内容基线。

真实 restore/setup 必须失败关闭：选定插件未安装、版本/字节不一致、启停错误、必需Skill未加载或无法核验时不得进入 restored；verify使用同一检查器，重试不会把旧回执当新证据。每次结果记录验收范围，完整环境状态继续为未完成直到项目、认证与设备验收另行满足。

## 验收

- 红测固定：零退出但插件缺失/错误版本、已经存在但内容不同、disabled、同名不同市场、损坏快照/遍历/链接/凭据、runtime不可用均不能假成功。
- 目标副本升级：保留无关配置、设备身份、记忆及登录引用；同版本目标修改拒绝，原内容不变；旧artifact无快照不破坏既有Skill/MCP流程。
- 定向测试 → npm test → typecheck/构建 →生产包消费者检查；全测失败不提交。
- 真实隔离Codex安装fixture（包含未提交定制），fresh app-server从安装缓存发现同一Skill；返回同步和双改拒绝用两个隔离设备目录实测。Hook待信任保持明确状态，不能为了测试信任真实Hook。
- 独立审查在固定差异上执行。主协调者核对实际代码与日志，不能只引用执行者总结。
- 本机正式U同步升级前说明影响/回退，备份现有来源/配置并保留2.2.2；仅安装本次工具更新，不同步或覆盖真实个人插件和工作区。真实惠普验收未执行单独报告。
- 提交只包含本任务增量，合入master并推送既有origin，核对远端完整SHA。用户旧开发分支和未提交文件保持不变；父工作区指针如不属本次任务不混入。

版本判级预计2.3.0：已有同步大功能内增加固定内容交接和用户可见验收小流程（Y）；命令假成功/来源误判为同批Z修复。未更换核心架构或扩大整机迁移完成标准。最终版本依实际差异核对。

## 2.5.0：Git 范围与实际运行内容

`backup --all --workspace-files git-only` 使用原引擎、私人配置仓库和各项目 origin；未选择时保留严格 `report-all`。只把用户明确暂缓的非 Git 文件计入排除，真实项目错误与必要插件缺口仍计入失败。暂存、冲突、远端目的地和凭据检查保留；干净关联分支或分离 HEAD 可通过实时远端祖先关系证明已有备份，不改工作版本。

插件快照仍为 schemaVersion 1，可选 `captureMode: runtime` 使收集、恢复及再次核验一致。声明入口、Skill 引用和传递依赖保留；开发测试、本地凭据和未引用工程资料列为排除。单文件上限由历史8MiB改为100,000,000字节，每组512,000,000字节，并限制解码大小。已知运行格式检查结构及可解压内容，未知格式拒绝；源码静态解析只解决语法确认的引用、编码和完整例子，不执行源代码、不按作者放行，真实字面量与相邻凭据仍扫描。

TypeScript 解析器是固定生产依赖，打包消费者测试必须在没有开发依赖的正式安装中调用捕获。npm tarball 默认不带 package-lock，正式 Codex 运行目录准备步骤附带与来源一致的锁文件；恢复依赖通过既有可信 npm ci 路径，不能把开发 node_modules 复制进快照。缓存只保留已验证路径和SHA256元数据；每次仍检查规范Base64、大小、路径及真实字节摘要，内容变化不能复用旧结果。

Git-only 的备份完整性按实际内容判断：没有下载来源的本地 Skill 必须在同一份个人文件清单中有真实入口文件，已声明的 Python/JS/TS 相对运行依赖保留。宿主环境变量只保存名称、目的机重建，并明确列为排除；原状态的迁移准备标记仍可为 partial。插件缺失、内容捕获失败、未解释的 partial、扫描诊断仍阻止备份完成，不改写旧快照或把目的机环境标为可用。

超过100,000,000字节的完整状态使用有原大小及SHA256的 gzip 存储封装，压缩文件仍受同一 Git 上限限制，解码最大512,000,000字节。导入、拉取、安装、校验和差异流程统一解码后继续原有内容验证；未知编码、损坏、超限和递归封装拒绝。普通 JSON 快照保留原格式，新封装要求恢复端使用2.5.0及以后版本。
