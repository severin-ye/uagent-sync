## 共同维护规则

1. 每次开始前 fetch 同一分支；在独立目录或干净工作树中同步最新清单。更新前再次检查远端，避免覆盖另一端的新状态。
2. 保留任务 ID。状态只用“待办 / 进行中 / 阻断 / 已完成 / 不执行”；“已完成”必须附本机命令、退出码、验证 SHA 和可跨机读取的脱敏报告链接。
3. 各机优先更新自己负责的行。共同任务由表中主办端汇总，另一端补独立证据；不要替另一台机器勾选未经确认的实测或安装状态。
4. 遇到新增问题，在相应阶段追加新 ID，不删除失败记录。报告尽量用每台设备独立目录，减少同时编辑冲突。
5. 提交仅包含本次任务清单/报告或明确的代码修复范围；push 被拒绝先取回远端并合并，不强推。代码修复与文档回传分开提交，修复依项目规则测试。
6. 保留真实配置、记忆、原始验收证据；不擅自替换设备身份、不修改运行中的配置或插件缓存、不上传个人快照到公开源码仓库。
7. 不把程序测试、报告上传、插件配置条目出现，分别冒充完整迁移、真实资料往返或插件安装成功。

## 每轮交接提示词（两端必须执行）

用户通过复制提示词在两台设备间传递任务，不假设另一端会自动收到消息或自行运行。

1. 每轮完成或遇到无法继续的阻断时，更新本清单和脱敏证据；有可回传内容时推送同一分支，并核实远端提交。推送失败必须明确说明，不能让另一端读取不存在的提交。
2. 最终回复必须附一段可直接复制的“给荣耀的提示词”或“给惠普的提示词”，不能只给报告链接、状态或让用户自行概括。
3. 提示词包含：接收设备、仓库与分支、实际交接提交 SHA、清单/报告路径、本轮完成与未完成项、对端下一步任务 ID 和具体完成条件，以及真实配置/记忆/原始证据的保护要求。
4. 区分“交接报告提交”与“待验证源码提交”；如果对端要复验，必须明确指定源码 SHA，不能把分支前进当作已验证新代码。
5. 明确要求接收端完成后同样更新清单、推送脱敏结果，并返回给另一端的可复制提示词，逐轮往复。阻断时写清所缺输入及可独立推进的任务，不无限重复同一检查。
6. 只有最终验收项有充分证据时才结束接力；最后一轮提示词用于请求对端核对结项，不能把尚未完成的安装、恢复或同步任务宣称为完成。

提示词结构：

> 你在【接收设备】。请读取【仓库/分支】最新清单，核对交接提交【SHA】及报告【路径】。本轮已完成【任务与证据】，仍未完成【阻断与边界】。请执行【任务ID、具体行动、完成条件】。如需复验，验证对象为【源码SHA】。保留真实配置、记忆和原始证据；仅上传脱敏材料，不强推。完成后更新清单、推送结果，报告实际提交，并返回一段可直接复制给【另一设备】的提示词，继续下一轮；遇阻断如实交接。
