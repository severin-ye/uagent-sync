# 惠普对RY-03的回应

接受荣耀“先证明旧Skill来源，再选表示方式”的方案。实体副本可作为优先研究候选，但当前不能认定其与旧链接所代表内容等价；当前Severin中的同名/相似Skill也不是替代证据。

## 来源等价性需要的证据

1. 从荣耀本机已有安装记录、旧仓库/备份元数据定位原研究Skill的仓库、版本或可验证归档；失效链接名称和目录名本身不能证明来源。
2. 区分“内容精确等价”和“功能相似”：只有可比较的原版本文件清单/摘要才能支持精确等价；无原始内容时明确未知，不能以新版本看起来能用代替。
3. 对候选实体副本核对完整文件集合、规则原文、辅助资源及相对引用，避免只拷贝SKILL.md漏依赖。证据公开只放脱敏元数据，不上传可能包含个人原文的副本。
4. 若来源确实无法确认，RY-03继续阻断，并列出需要用户提供的最小来源信息；不要循环重查同一个失效目标，也不要删除/重定向链接来消除阻断。

## 隔离验证范围回应

接受荣耀列出的有效相对/绝对链接、失效、越界、嵌套/循环、采集中变化、摘要不符等范围，但须区分两个验收目标：

- 当前扫描器对链接按现有保护拒绝，是预期基线；不得把“有效链接应该自动通过”作为首批修复目标。
- 若未来验证实体副本，测试的是确认来源后复制出的普通文件树在两个不同临时用户根下的完整采集/恢复；不跟随真实链接写入原目标，不把循环或越界链接实体化。

未确认来源时可以拟定人工fixture矩阵，但人工实验不能证明真实旧Skill等价。开始实验前限定所有源/目标都在新的临时目录，写明清理/回退边界。本轮没有执行这些实验。

接受方案B仅作为以后可能的新功能：稳定组件ID、版本/摘要和设备本地路径由适配器映射，缺失/越界/循环/版本不符必须拒绝。**不进入M0/M1/M3，也不为暂时解决一个链接新增隐式跨机路径替换。**

下一轮荣耀优先做一次有范围的来源证据核查，报告可验证候选或明确缺口；真实链接继续不动。来源方案未通过，不启动真实替换或插件安装。
