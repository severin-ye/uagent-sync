# 合同逐项复核

## 解析器

| 合同 | 结论 | 必须明确的边界 |
|---|---|---|
| A 固定依赖 | 接受作为候选 | 1.1.18上游声明支持ESM，但实际npm包、lock中lr/common/highlight版本、Node18及打包入口均未验证。上游固定提交不能替代resolved版本。 |
| B S0 输入 | 接受，需分层 | 纯字符串函数无法追溯此前是否用替换字符解码了坏UTF8；字节读取层负责严格解码，M2层负责BOM/换行约束。不可在扫描器层假称验证原字节，也不把合法U+FFFD一概当解码失败。 |
| B S1 整文件 | 接受，补原始词法闭合门槛 | strict与isError只描述该grammar的解析，所有String/FormatString（含候选之后）均须核对真实闭合；未知格式无法证明则M2整文件弃权。禁止仅检测零宽节点就一律拒绝，EOF/缩进相关合法零宽结构需区分。 |
| B S2/S3及异常 | 接受 | pending必须在完整遍历、词法和参数不变量完成后才返回；任何内部异常均不能泄漏pending。无M2掩码、危险输入拒绝、无副作用分别验证。 |
| C 函数父子关系 | 接受 | Script直接FunctionDefinition、无async/Decorator；显式把TypeParamList加入首批非候选范围，不能因grammar支持而自动允许泛型函数。 |
| C 参数 | 接受方向，节点合同待原型 | param是小写规则，可能没有逐参数节点。仅取ParamList所有直接VariableName也不够：默认Name表达式可与形参同级。需真实树+分隔符状态界定参数、TypeDef和默认表达式，不能按descendant名字猜测。 |
| C 参数合法性 | 需补规则 | 唯一裸*后必须有keyword-only参数；位置参数有默认后不得出现无默认参数；全部参数去重。保留对/、*args、**kwargs的首批弃权，keyword-only有/无默认的顺序不能套位置参数规则。只对候选签名作这组额外检查，不宣称全文件CPython语义验证。 |
| C 首语句/String | 接受 | 必须原表达式范围恰好等于单个String；ExpressionStatement可能包含逗号表达式，不能只因有一个String子节点就允许尾逗号、解包或其他表达式。Body块式判定须用真实换行/缩进及树形，不凭节点名。 |
| C Args归属 | 接受，明确歧义处 | 唯一标题在本docstring内；api_key只出现一次应明确为“参数条目名”，不是任意正文子串。下一同级参数应符合条目语法并关联该函数形参；退回节级需可识别完整标题/结束引号，未知段落弃权。空行不自行终止条目。 |
| C 不支持行为 | 接受，需统一原因表 | “合法但非候选”可跳过；无法证明文件词法闭合/候选签名结构时清空全部M2候选。不要把两种情况混成局部恢复。明确多候选中后者撤销前者。 |
| D 原始位置 | 接受 | from/to按未归一化JS字符串；验证LF/CRLF、前缀与更早行非BMP。原始字节校验和UTF16索引分别断言。 |

静态依据：固定[grammar](https://github.com/lezer-parser/python/blob/091aab4b36d8e430053ee5603db170cd4eaec776/src/python.grammar)第24–31、77、106、115、144行展示函数、参数、表达式和Body规则。固定[tokens.js](https://github.com/lezer-parser/python/blob/091aab4b36d8e430053ee5603db170cd4eaec776/src/tokens.js#L192)第192–198行对非长字符串在换行处产生不消费引号的结束标记。这是G0必须验证的具体风险，不是本轮运行失败结论。

## 私有模板

| 合同 | 结论 | 明确后才能接入 |
|---|---|---|
| 来源 | 接受 | 私有路径/正文由明确获授权的本机操作者准备；本轮没有准备授权或真实模板。D1–D3审核关系保留，不以“可读文件”证明可信。 |
| provider | 接受原则，接口未落定 | 指定顶层宿主构造可信provider，普通扫描参数、manifest、同步配置、被检目录均不得转成provider来源。原型用注入人工字节源；生产注入点尚需调用图核对。 |
| 封闭schema | 有条件接受 | 顶层仅schemaVersion/policyVersion/parserVersion/entries；版本与field精确值、D1–D3恰各一次。数组顺序不影响按ID匹配，描述三组应互异。明确重复JSON键的拒绝方式，不能以JSON.parse后的对象证明原始JSON无重复键。 |
| 内容及上限 | 接受精确匹配 | JSON解码只作用模板数据；受检正文不unescape/trim/归一化。确定模板字节上限和单项长度上限，作为拒绝资源门槛，不作允许规则。原型可用16KiB整体/256 UTF16单元每项作为明确实验上限，尚非生产定值。 |
| 版本 | 接受 | 与代码支持的policy/schema及实际锁定依赖来源对照；不信模板自报版本。原型记录resolved版本，打包后版本证据单列，无法核验则不激活。 |
| 冻结及竞态 | 接受，明确每操作语义 | 每次操作枚举文件前加载一次，验证后复制并深冻结；该操作所有文件共用此对象。并发操作各持有独立快照，不使用模块级可变currentTemplate；更换源仅影响后续操作，不回用旧缓存。 |
| 缺失/失败 | 接受 | 缺失、读取、schema、版本、内容及内部错误返回无模板/无M2掩码；固定不含路径或正文的原因码。不要要求检测所有未观测竞态，原型证明读取/复制中故障不会产生部分对象即可。 |
| 三入口 | 接受 | 共享provider实现和验证合同，不要求三次操作同一实例；真实接线和无副作用需要未来独立集成验收，本轮只有设计。 |

新增测试补充不是本轮执行结果。G0须把上述原始闭合、参数状态、逗号尾部、TypeParamList、重复JSON键、操作内一致/操作间隔离加入人工测试；沿用T01–T12、G1其余门槛，不重做真实四处或172项。
