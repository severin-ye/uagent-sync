# HP-02 最小修复方案（待荣耀复核，未实施）

## 决策范围

首批建议只处理两机共同23处中语法充分明确的20处：9处环境/参数引用、4处参数说明、7处API占位符。两处固定密码示例、一处未确认令牌形字面量，以及荣耀额外172处全部继续阻断。20是现有证据对应的候选覆盖数，不是已修复数，也不是完整快照会通过的承诺。

不重写用户原文件、不改manifest、不整体取消扫描、不按扩展名或目录名豁免。未知表达式、非空字面量和不完整语法按原策略拒绝。

## M0：先防止同一行的其他凭据被跳过

源码审阅发现 `src/lib/secret-scan.ts` 的 `scanForSecrets` 在一行含 `<hidden>` 或 `<YOUR_...>` 时直接 continue；这会让同一行的另一处真实凭据不再检查。属于源码判断，当前未执行新增测试来复现，必须先增加 T00/T01 红测，不能将其当作已修复。

建议只忽略明确占位符的局部跨度，继续扫描该行剩余字符，不能用插入 `<hidden>` 来令整行静默。现有profile规范化也应保留行号并仅移除已经完整识别的表达式跨度。同一行相邻命中、跨行回退及同名字符串中的命中均需测试。

基础扫描器还被 `codex-restore.ts` 的恢复配置/安全报告检查使用；profile扫描被快照采集、恢复读入、`device-git-transport.ts`发布候选扫描复用。实施前对拟修改符号运行影响分析，并给出调用范围，不能为了profile通过破坏其他入口。若基础扫描器改动无法足够隔离，则将M0作为先行独立修复提交；本轮不作代码更改。

## M1：只扩展完整、无字面量凭据的引用表达式

- Python环境读取：在已有单参数 `os.environ.get` 规则上仅增加第二参数为精确空字符串的形式。非空默认值、任意表达式默认值、`or`非空回退继续扫描/拒绝。
- Python参数成员：仅首批观察到的 `args.api_key` 完整RHS或调用实参形式；明确结束边界。不能把匹配前缀当作整个表达式，也不把所有看起来像标识符的未加引号值当作安全。
- `api_key=args.api_key` 不携带运行时值；若文件中别处给args写入真实值，那个位置仍必须命中。
- 现有 `process.env`、Java/C# 环境读取兼容性保留。TS对象属性、任意变量引用、随机生成函数等不在首批支持中；等荣耀补齐结构后再扩展。

优先范围：`profile-secret-scan.ts` 的有限语法规范化；不要直接放宽全部 `sensitive-assignment` 字符范围。

## M2：参数文档误报只按明确上下文处理

四处当前文本是Python三引号参数说明中的“Optional API key …”，而非凭据值。候选做法：在确认docstring上下文和完整固定说明语句后，仅跳过该说明跨度。不得整个docstring、注释、Markdown段落或包含Optional单词的行免扫。文档内的真实赋值、Bearer、令牌前缀仍按原规则拒绝。

如果实现需要引入宽泛/脆弱的多语言解析，则暂缓M2，保留四处阻断；不以扩大豁免换取完整快照通过。

## M3：API示例只考虑精确完整占位符

七处共同SDK示例经本机私密比较确认均为精确 `your-api-key` 字面量。建议在可识别的敏感参数/属性示例局部支持这一有限占位符，覆盖已见Python、PHP、Ruby、TS语法；不得以含your/example等词的模糊正则认定安全。

完整值和结束边界是必要条件：前后缀变体、字符串拼接、同一行另一个值或同一文件其他令牌必须仍被扫描。格式无法完整识别时不放行。文档来源只辅助解释，不作为文件级豁免。

## M4：暂缓字面量和未知项，不能承诺全部通过

- 两处qpdf常见密码即使有演示语境，也可能是实际密码；不加入全局固定密码白名单。
- 工具文档的令牌形字面量保持未确认；不能凭示例标记特征判断非凭据。
- 测试fixture、`.env.example`、dist中的值没有天然豁免。不得将“未证实为真实凭据”写成“已证实安全”。

如业务确需原样迁移经人工核实的固定示例，另行讨论逐处审核例外：至少绑定规范化相对路径、整个源文件SHA256、规则、精确跨度和匹配指纹；文件或跨度变化即失效，仍扫描其他跨度。只记录无秘密的审核元数据，不把审批字段写入用户原文。**此机制不属于本轮或首批HP-03的默认实施范围**，必须先评审采集/恢复/发布三端如何一致核验，不能只在采集端绕过。
