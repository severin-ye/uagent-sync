## 当前项目是什么

U同步 2.1.1 是 TypeScript 单进程工具，提供 CLI、OpenCode Plugin、Codex Skill 入口和本地管理界面。公共流程经过 Application 层，调用现有领域模块和基础设施适配器；不是两个电脑之间的常驻文件同步服务。

- `src/cli.ts`：命令解析和输出。
- `src/application/`：export、import、push、pull、setup 等流程。
- `src/lib/state.ts`：读取并整理宿主状态。
- `src/lib/codex-restore.ts`：Codex 扩展恢复。
- `scripts/bootstrap.ps1`：新 Windows 的基础工具和插件引导。
- `usync-dotfiles`：父工作区中的独立 Git 仓库，保存同步产物；不等于整个办公目录的备份。

### 已实现与缺口

| 对象 | 现有行为 | 对本次目标的影响 |
|---|---|---|
| Codex 扩展导出 | 从 live TOML、marketplace 和 Skill 索引提取插件、Skill、MCP | 能更新扩展索引，不能视为完整配置备份 |
| Codex 项目导出 | Codex artifact 的 `submodules` 固定为空 | 不能凭 Codex export 迁移所有项目 |

| Skill / MCP | 有来源核查、删除标记、安装与失败报告 | 可复用现有恢复逻辑 |

| dry-run | import dry-run 只比较部分对象；pull dry-run 仍先 git pull | 不能把所有 dry-run 当成绝对只读 |

## GitHub 传输的边界

用户的“全部内容”必须落实为完整的文件覆盖报告，不能偷换为“全部 Git 跟踪文件”。

- 代码、文档、小型个人配置和适合 Git 的资料：通过已有私有仓库及子仓库。
- 大文件、数据库、被忽略但有价值的成果：先按文件清点大小、用途和隐私属性，再选择 LFS 或独立传输包，保留内容校验；本方案尚未决定新增收费存储或外部服务。
- `node_modules`、`.venv` 等安装环境：保留依赖版本和安装来源，在惠普重建并实测。用户目录不同，直接复制虚拟环境不等于可运行。无法重建或包含人工修改的内容必须报告，不能自行丢弃。
- 密钥和登录状态：只同步引用及缺失检查；需要实际值的项目单独安全配置，不能明文加入 Git。其他个人资料只进入明确私有的目标。

GitHub 普通 Git 文件超过 100 MiB 会被阻止，官方也明确 Git 不适合作为完整备份工具：https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github 。因此不应对整个目录执行无差别 `git add -A`。

## 配置与路径迁移

设备映射：荣耀 `%USERPROFILE% = C:\Users\6seve`，惠普 `%USERPROFILE% = C:\Users\severin`。工作区均位于各自用户目录的 `Codelib-severin`。

可迁移配置使用用户目录、工作区和插件根目录占位符；目标机导入时生成实际路径。转换仅限明确的配置字段，不能全目录文本替换用户名，破坏历史原文、代码字符串或二进制内容。跨用户名的插件入口、MCP 启动命令和引用路径都需要验证。

共享配置与机器专属配置应分开。登录令牌、设备身份、宿主信任、运行锁、活动 SQLite、机器端口与本机缓存不能简单覆盖。Codex 项目配置的加载还受宿主信任控制，文件复制不能代表宿主已信任：https://learn.chatgpt.com/docs/config-file/config-basic 。

## 首次迁移与日常交接

首次：清点荣耀 → 保存惠普现状的可回退副本 → 完整保存源机可迁移状态 → 通过 GitHub 传输适用内容 → 惠普恢复并映射路径 → 重建依赖/完成必要认证 → 逐项验收 → 建立双方共同基线。

日常：上机先检查本地未交接改动 → 拉取上一台已完成的交接 → 冲突处理与恢复 → 工作 → 下机采集变更 → 检查遗漏和凭据 → 上传交接 → 确认远端可取。两台均修改同一文件时保留双方版本并阻断覆盖；不按机器时钟判定胜负，也不自动 force push 或 reset --hard。

历史对话首版不作为成功条件。若以后增加，单独评估会话文件、数据库、附件、路径引用及恢复后的可见性；拷贝 JSONL 不代表在侧栏可继续原任务。任务文档和记忆先行保留。

## 实施顺序

| 事项 | 现在是什么样 | 准备改成什么 | 依据和理由 |
|---|---|---|---|
| 文件覆盖核查 | Git 未覆盖全部内容 | 生成工作区与 Codex 的完整分类报告，明确缺失、体积、来源和恢复方式 | 先证明没有遗漏，再选择传输 |
| Codex 个人快照 | 只有扩展索引，当前清单还缺宿主作用域 | 独立保存配置、规则、Skill 来源、Severin 版本与必需记忆 | 不能覆盖旧项目快照而丢失项目信息 |
| 跨机器路径 | 当前含荣耀绝对路径 | 配置字段占位符与荣耀/惠普设备映射 | 支持不同用户名 |
| Git 工作区交接 | 只 push 状态文件 | 核查父仓库、子仓库、未跟踪/忽略文件和远端可获取性 | 不能把状态上传当作文件传输 |
| 双向冲突与回退 | 无完整交接基线 | 共同基线、目标备份、冲突保留、失败不更新完成状态 | 保护两台各自产生的新内容 |
| Severin 联动 | 无专用换机入口 | 个人 Skill 调用 U同步正式能力并关联任务状态 | 一套同步实现，统一用户入口 |
| 实际验收 | 仅荣耀预检，恢复清单失败 | 隔离测试后完成惠普恢复及一次惠普到荣耀回传 | 双机结果才能证明双向可用 |

## 验收要求

- 原有惠普内容有明确回退位置，首次主副本选择有记录。
- 全部工作区内容有去向；传输、重建、可选不恢复、失败项分别报告，不静默排除。
- 必需文件内容校验一致；子仓库目标提交远端可取得。
- 惠普实际打开目标工作区，关键项目按其已有启动方式可用。
- Codex 插件实际 installed/enabled，Skill 可发现，MCP 可运行；配置路径不残留错误的源机用户目录。
- Severin 规则版本一致，记忆原文保留，必要宿主信任在目标机真实完成。
- 在惠普改一个测试文件并交接回荣耀成功；模拟双方修改同一文件时不会覆盖任何一方。
- 历史对话是否恢复单独报告，不让可选失败掩盖或阻塞必需项。

在这些检查通过之前，不能称“完美复刻完成”。
