## 验证顺序

### A. 全套回归

运行 `npm test` 并保存完整日志。先记录测试是否采用真实用户目录；若既有配置污染测试，只在子进程临时 USERPROFILE 下重跑，恢复原环境变量，分别报告两次结果。隔离目录通过不能冒充真实环境通过。

### B. CLI 隔离交接

在唯一临时目录建立两个模拟 userHome、codexHome、workspaceRoot，一个 registry 目录及两个不同 connection 文件，避免写入真实 `~/.codex/uagent-device.json`。命令参数从 `device help` 和 `docs/DEVICE-SYNC-USAGE.md` 核对。

1. 分别 `device register --connection ... --registry ... --remote https://github.com/example/private-registry.git --name ... --workspace-id main --workspace-root ... --user-home ... --codex-home ...`。这里只验证登记，不调用 fetch/publish，不把示例远端当成真实仓库。
2. list/show：两个 ID 不同；重复登记保留 ID；rename 不改变 ID；使用任意别名验证代码没有依赖荣耀/惠普字符串。
3. 在模拟源目录准备无凭据的 config.toml、AGENTS.md、一个本地 Skill 和 memory 文件。snapshot 默认覆盖四类组件。restore 默认预览不得写目标；apply 后比较文本及路径映射。
4. 目标已有不同文件时，普通恢复应冲突；仅模拟首次迁移使用 prefer-source，核对备份原文。后续两边同时改同一文件必须冲突，不能继续用 prefer-source 覆盖。
5. 单独验证反向交接：从第二个模拟设备生成快照，在第一个设备预览并按适用基线处理；首次反向若无基线，应报告/解决冲突，不可宣称已经具有双向自动合并。
6. 核对 tests 中路径逃逸、链接、密钥、复制中变更、覆盖保护的结果。不要为通过修改扫描规则或删除保护。

### C. 惠普真实状态兼容性

只读检查真实 Codex 配置、Skill 链接、插件安装来源以及现有工作区；如需通过代码采集，输出到独立临时目录，并使用显式目标路径，不能将真实配置复制回运行中的 Codex。

生成本机个人文件快照是允许的本地备份操作；失败须保留完整的脱敏路径/规则报告。不要把本机快照上传公开源码仓库。默认完整采集被阻断时，可另跑 config,rules,memories 并明确 skills 未覆盖。

检查 U同步 Skill 可发现性和 Severin 当前安装版是否具有设备交接入口，分别记录源码、安装、宿主加载三种状态。没有入口就记录未安装，不能直接编辑缓存冒充升级。真实插件安装和跨电脑资料恢复必须有对应来源及经过验证的版本。

这次不要自动向用户配置仓库提交测试文件。可读取已有私有仓库连接和认证状态，但不能假设本分支携带了源机快照。
