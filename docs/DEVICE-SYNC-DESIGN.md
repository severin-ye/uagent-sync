# 模块化多设备办公环境与 Codex 同步设计

状态：2026-09-11 已新增设备注册、路径资料、配置仓库连接、覆盖清单、个人文件快照与保护恢复、显式 Git 传输接口。当前使用与验证缺口见[运行说明](./DEVICE-SYNC-USAGE.md)。完整项目交接、Skill 来源恢复及真实第二台设备验收尚未完成；下文仍保留目标架构，不把所有设计项当成已实现。

## 目标与边界

支持任意已登记设备通过可配置的 GitHub 仓库交接工作区和 Codex 个人环境。设备名称、用户目录、工作区位置、配置仓库地址都属于配置数据，不能写死在 U同步或 Severin Skill 中。

“荣耀”和“惠普”只是目前两台电脑的别名。首次以其中一台为准，是一次迁移任务的选择，不是永久主从关系；后续任意设备均可发起或接收交接。当前只验证 Windows 场景，多设备设计不等于其他操作系统已经受到实现支持。

## 模块边界

| 模块 | 负责 | 接口边界 |
|---|---|---|
| 设备登记 | 稳定 ID、用户别名、系统类型、路径映射、参与的工作区 | 同步逻辑读取设备资料，不依赖名称判断行为 |
| 同步配置 | 工作区定义、同步对象、忽略与重建策略、配置版本 | 配置独立保存，不随扩展升级被覆盖 |
| 采集与恢复适配器 | 工作区文件、Git 项目、Codex 配置、Skill、插件、记忆 | 按对象类型采集与恢复；Severin 作为插件及个人资产接入 |
| 交接引擎 | 差异、共同基线、冲突、备份回退、结果验证 | 输入源设备、目标设备及同步范围；返回计划与真实执行结果 |
| 存储与传输 | 获取、校验、提交与传输清单和适用文件 | 首版使用 Git/GitHub；仓库地址和本地 checkout 可配置 |
| Severin Skill 入口 | 理解“换电脑继续”等意图，选择已登记设备，关联任务状态 | 调用 U同步，不维护另一套设备表或同步算法 |

这些是单个项目内部的模块，不需要拆成多个服务或每个模块单独建仓库。只有配置和用户数据需要与工具源码分离。

## 配置存在哪里

推荐先使用已有私有 `usync-dotfiles` 仓库中的独立目录；该仓库已经承担用户配置与同步产物存储，避免立即引入新的仓库和认证负担。以后可以将同一目录结构迁到独立私有仓库，只修改本机连接配置，不改变交接引擎。

建议目录结构（均为待实现）：

```text
<配置仓库>/
  sync/
    registry.json               # schemaVersion、工作区定义、设备索引
    devices/
      <device-id>.json           # 每台设备独立资料
    policies/
      default.json              # 共享的同步与冲突策略
    handoffs/
      <handoff-id>.json          # 已发布的交接清单
    receipts/
      <device-id>/              # 各设备的恢复验收回执
  agents/
    codex/                      # 复用/演进现有 Codex 资产结构
```

首版设备很少时，设备资料也可合并为一个文件；推荐每设备一文件，减少两台同时编辑同一注册表造成的冲突。不重复保存同一配置的两份权威版本。

配置仓库不是整个办公目录：工作区项目继续由各自 Git 仓库保存；大文件和不可重建的忽略文件需要独立覆盖与传输策略。配置仓库记录其来源、版本和校验信息，不能以一份索引冒充全部文件已经备份。

## 本机连接与共享登记分开

每台机器本地保存连接配置，用于找到配置仓库和识别自己，概念字段为：

- `deviceId`：初始化生成、持久保存的稳定 ID。
- `registryRemote`：配置仓库地址。
- `registryCheckout`：本机配置仓库 checkout 路径。

本机连接配置不能整体同步覆盖另一台，否则会把两台识别成同一设备。GitHub 凭据仍使用本机凭据系统，不写入登记文件。

共享设备资料示例（说明格式，不是已经生效的配置）：

```json
{
  "schemaVersion": 1,
  "deviceId": "example-device-id",
  "displayName": "用户自定义别名",
  "platform": "windows",
  "paths": {
    "userHome": "C:/Users/example",
    "codexHome": "C:/Users/example/.codex"
  },
  "workspaces": {
    "main-workspace": {
      "root": "C:/Users/example/Codelib-severin"
    }
  }
}
```

`deviceId` 不使用别名、用户名或硬件型号生成身份判断；别名可改，路径可变，ID 保持稳定。别名重复时让用户选择，不能猜测目标。重装后是否接续原设备身份需要明确恢复流程，不能因为同名便自动继承旧基线。

每台只修改自己的设备资料；公共工作区或策略变更按 Git 冲突处理，不按文件时间静默覆盖。设备声明支持什么与实测支持什么分别保存，验收回执记录实际结果。

## 路径与机器差异

共享配置使用语义占位符，例如用户目录、Codex 目录、工作区根目录。适配器在导出时识别支持的路径字段，在恢复时按目标设备映射生成实际值。

路径转换只处理明确的配置字段，不对代码、记忆、文档、历史记录或二进制做全局字符串替换。尚未识别的源机绝对路径列为检查项，不能伪报完全可迁移。

配置优先关系为：共享默认值 → 工作区配置 → 目标设备覆盖 → 本次显式选项。有效配置需展示来源；本机认证、设备身份、活动数据库与锁、宿主信任不因共享配置被自动覆盖。

## N 台设备的交接

交接记录引用 `sourceDeviceId`、目标设备 ID 或允许接收的设备集合、工作区 ID、配置版本、源文件/提交版本及待恢复对象。接收设备按自己的最后成功基线判断差异，不固定维护“荣耀对应惠普”的单一关系。

推荐流程：

1. 登记或识别当前设备，读取其工作区映射与同步范围。
2. 获取远端清单，检查本机未交接变更和远端变化。
3. 生成差异计划；同一对象双方有不同修改时保留双方并阻断自动覆盖。
4. 备份受影响目标，执行传输、恢复、路径转换及必要依赖重建。
5. 验证成功后记录该设备回执与新基线；失败保留可回退状态，不标记已完成。

首次迁移中的“以源设备为准”属于本次操作参数，只适用于选定范围并要求保留目标回退条件。不能把这一选择写成永久策略，覆盖之后在其他电脑产生的新内容。

并发发布时检查远端是否已前进；基线变化后重新比较，不强推。设备离线一段时间再回来，仍从自身上次成功基线与最新远端比较。

## Severin Skill 如何联动

个人 Skill 通过 U同步查询设备列表，再把用户提及的别名解析为设备 ID。它不写死设备名称、目录或 GitHub 地址，也不复制设备登记文件。

“准备换到某台电脑继续”应转化为：确定当前设备和目标设备 → 保存适用的任务状态 → 调用 U同步生成交接计划 → 在已有授权范围内执行 → 按真实结果说明是否可接续。

Severin Skill 本身的版本、安装来源、规则和必需个人记忆作为同步资产，由统一采集恢复模块处理。记忆原文保留；历史对话维持可选。个人 Hook 的活动锁、待执行队列和设备端运行状态不能照搬到另一台。

## 实施计划

| 事项 | 现在是什么样 | 准备改成什么 | 依据和理由 |
|---|---|---|---|
| 配置契约 | 现有缓存用于定位单机工作区 | 增加有版本的设备与工作区配置，保留旧缓存兼容 | 新增设备不改代码 |
| 配置存储 | 设备信息尚未独立成模块 | 先放现有私有配置仓库，连接地址可替换 | 可独立迁仓，避免仓库绑定 |
| 设备身份 | 本次正文用机器别名称呼 | 稳定 ID 与可修改别名分离 | 改名不破坏同步历史 |
| 路径处理 | 仅描述两台已知路径 | 用设备映射和类型化配置字段转换 | 兼容任意用户名和目录 |
| 交接基线 | 无完整多设备共同基线 | 每设备保存最后成功恢复记录，冲突阻断 | 支持第三台与离线回归 |
| 个人扩展联动 | 尚无专用换机入口 | 查询统一设备注册并调用 U同步 | 不重复维护设备信息与算法 |

## 验收标准

- 新增第三台设备仅新增配置，不修改源代码或 Skill 正文。
- 修改别名仍能找到同一设备历史；重复别名不会误选。
- 不同 Windows 用户名和自定义工作区路径均可恢复。
- 配置存储迁到另一私有仓库后，更新连接配置即可继续识别设备与历史。
- 各台连接文件保持自己的 ID，恢复不会复制源设备身份。
- 首次主副本选择不影响后续任意设备双向交接。
- 双方修改、远端前进、离线设备回归均不静默丢失内容。
- 完整环境覆盖和两台真实验收仍遵守[首次迁移实例](./HONOR-HP-SYNC-DESIGN.md)；设计完成不代表迁移实现完成。
