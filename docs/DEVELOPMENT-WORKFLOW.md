# 开发协作指导：成批推进与集中验收

## 适用范围与入口

本规范适用于本仓库所有设备、工作目录及开发终端中的 Agent，包括 Codex、Claude、OpenCode 和用户转交任务的其他工具。开始开发前读取本文件；交接时要求接收端拉取并读取，不以终端名称区分标准。

这是共同工作约定，不是终端进程拦截器。已运行的会话须主动重新读取；不支持自动加载仓库规则的工具，由任务提示词明确引用。其他仓库采用时在其自身规则入口引用，不声称本次已部署到所有项目或惠普运行环境。设备路径与名称继续从正式设备配置读取。

用户明确限定只读、只审方案、独立复核或禁止真实操作时，服从该范围。本规范不自动授权生产集成、真实模板读取、采集、安装、恢复、链接替换或快照发布，不替代安全检查。

## 1. 以可用交付组织工作

开头查清目标、现有证据和授权边界，一次集中提出确有必要的关键问题。已确定的范围不反复确认；普通技术选择、可逆修改、工具故障恢复和范围内回归修复自行完成。

以一个可独立验收的结果组成一个批次，写明负责人、源码基线、修改范围、完成标准和真实阻断。批次内连续完成复现、修复、相关回归、必要全量检查及报告，再交接另一端。不要每补一条测试、每改一段方案就让用户复制一次提示词。

同类边界应一次列出并覆盖，避免只修眼前一个字符串。新发现会改变安全或架构边界的问题单列处理，不为赶进度扩大允许范围。

## 2. 开发与独立验收的职责

执行端负责红测、修复及自验，直到该批次必要检查满足。复核端固定源码，在独立环境复核关键行为和攻击边界，不把执行端摘要当成证据。

纯独立复核发现漏洞时，保留最小人工复现并回传具体差异；不擅自改成开发任务。执行端收到已授权范围内的缺陷后直接修复，不再为相同方案开一轮确认。存在多个独立问题时一批回传，不逐个串行询问。

多终端写任务使用独立工作目录和任务分支，声明文件所有权；不让两个终端同时修改同一工作树。由协调端整合并核验远端，禁止强推和夹带他人未提交修改。设备接力继续使用共同清单及指定协作分支，不将未验收生产源码合入主分支。

## 3. 测试按阶段安排

- 修复前先保留能证明问题的红测；开发中运行与当前修改相关的定向测试。
- 提交代码或配置前必须完成项目要求的 npm test，以及相关构建、兼容性和打包检查。失败继续定位，不能删测试或降低断言换取通过。
- 固定交接源码后，复核端执行一次必要独立验收。无代码、依赖、环境变化且无新疑点时复用已有证据，不为文档确认重复完整测试。
- 新漏洞、修复或环境变化使旧证据不再适用时，按影响范围重新验证。安全拒绝必须覆盖无副作用，不以环境错误冒充预期拒绝。
- 仅文档改动检查内容、链接和差异，不为增加测试数字运行无关全量程序测试。

隔离用户、应用、Codex、临时目录及 npm 配置/缓存；明确清除不应继承的工作区变量并记录执行前环境。测试可切换自己的 fixture。消费者安装前创建 private package.json，使用明确的目标目录和 --prefix，检查祖先依赖污染；不得在真实用户目录试装。

## 4. 控制范围，尽早处理迁移阻断

扫描器无法确认的表达式保持拒绝，不持续扩写成通用语言解释器。不采用整行跳过、目录白名单或关闭扫描来提速。先判断增加识别能力是否确为当前交付必要条件。

一次整理所有剩余阻断，记录证据、负责人、最小输入和下一步，区分：Agent 可自行解决、必须由用户决定、可经用户同意另行完成。不在没有新证据时重复来源搜索。

已明确安全的内容可以提出先行迁移方案；实际选择部分范围或私下搬运必须取得对应授权。暂缓项保留原文和清单，不静默排除，部分可用不得称完整迁移完成。凭据与个人快照不得上传公开仓库。

## 5. 简化记录，保留可复核证据

共用任务清单是进度来源，历史报告保持不变。每批报告只写本批差异、固定源码、命令及退出码、通过/失败/未执行、剩余阻断和下一步，引用已有证据，避免复制整段历史。

正常进度说明新发现及下一步，不把日志逐条转述给用户。预计耗时只能是估计，优先报告距离可用交付还差哪些验收。

程序测试、打包、安装、真实恢复、双向往返分别记录。只有用户范围内的可用结果及必要交付均完成，才标记完成。

## 6. 每轮交接要求

交接前合并本轮所有已就绪结论，推送后核实远端完整 SHA。接收端只更新自己的任务状态，不代勾另一端。没有新证据或新任务时不制造确认提交。

交接提示词必须包含：

1. 仓库、分支、实际交接 SHA 与独立源码 SHA。
2. 本规范、共同清单和本批报告路径。
3. 本批已完成/失败/暂缓事项及保留证据。
4. 下一批具体目标、修改权限、验收标准和停止条件。
5. 明确要求接收端成批推进后一次回传；真实必要阻断提前报告，不能无限重试。

## 转交前必须做完本机可做的工作

协调端先完成共享仓库里不依赖另一台机器的取证、实现、修复、文档、脚本准备和验收。不得仅因当前小阶段结束，就把这些工作交给另一端。收到“把能做的都做完”的要求后，持续推进本次已授权范围；只审方案或只独立复核等明确限制仍有效，不能扩大为无限开发。

只有下一步确实需要另一台机器的本地状态、运行环境或设备验收，或者必须由用户作出的实质决定，才交接。前一端应提前准备具体命令、输入和通过标准；后一端同样先做完本机可做的全部已授权事项，再集中回传。禁止为了确认已知结论而制造空提交或重复方案轮次。

遇到一个阻断时继续完成不依赖它的其他工作。交接说明必须列出本机已完成什么、剩余事项为什么无法在本机做、接收端可以连续完成的任务。用户提供必要新信息前，不反复搜索同一来源或让两端互相转交同一个未决问题。
