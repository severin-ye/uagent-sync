# 解释一次已完成的更新

本流程由既有 update Skill 条件加载。默认口令：“U同步，讲讲这次更新”；同义口令：“U同步，整理更新说明”“U同步，这次更新了什么”。先识别解释意图，不能因为所属 Skill 叫 update 就运行更新或预览。默认解释最近一次真实更新中 Skills 与插件的实际变化；用户指定范围、批次或历史区间时沿用，不重复询问已有明确边界。

## 1. 确认批次与身份

先查当前任务已登记的更新报告、手工 Skills 更新收据、交付记录和回退资源；再按实际 workspace 与 CODEX_HOME（未设置时用宿主默认目录）发现：

- workspace 的 `usync-dotfiles/state/update-reports/`。
- `CODEX_HOME/uagent-sync/update-backups/` 与并列的 `CODEX_HOME/uagent-sync/update-baselines/`。
- 正式安装锁、插件 manifest、安装收据和对应旧备份。

路径从当前环境、配置和报告解析，不写死机器盘符、历史报告名或条目数。不遍历无关个人文件。按报告内容的 timestamp、targetAgent、源身份、组件及安装结果确定最近真实批次，不能只选文件名或文件修改时间；最新 dry-run 不能替代上一次真实更新。一个批次可能有多份报告与手工收据，按任务关联和目标身份合并，保留失败、跳过、部分成功和同版本刷新。以原远程 ID/源仓库/安装路径匹配组件，同名不证明同一来源；时间接近也不单独证明同批。

范围可从现有证据唯一确定就继续。多批冲突或旧新来源无法匹配且会改变结论时，只问一个关键范围问题；先整理已能确定的部分。没有真实更新证据时直说，没有运行更新的授权。

## 2. 还原旧新原件

对每个组件记录旧左、新右的身份、版本和证据路径。优先使用同一次更新保留的旧原件与新文件、不可变提交或固定产物；成功验收 baseline 只证明当时安装通过，不独立认证官方字节。当前安装若已漂移，说明它不是当时新版本的原件。

可对每份已确认报告调用现有只读证据入口：

```text
node <uagent-sync>/dist/cli.js changelog --target-agent codex --report-path <absolute-report-path>
```

替换为真实绝对报告路径；其他 Agent 使用对应 target。CLI 只输出版本变迁和 evidence，不能代替语义比较。报告不兼容或 CLI 不可用时直接读原报告并注明，不用重装修复来制造说明证据。

比较旧新 `SKILL.md`，并沿其引用读取与变化有关的脚本、references、模板和调用入口。版本采用组件权威字段，例如 package manifest、正式 VERSION 文件或锁定提交；不能把子 Skill frontmatter 或目录名误当聚合包版本。分别统计包/目录替换数量与独立 Skill 入口新增、删除、改变数量；聚合包与内含入口不可重复相加。

缺少旧原件时，可读取**对应旧新版本区间**的官方 changelog/提交记录并注明“文档依据，未完成旧新原件对比”；新版描述、最新网页或单边文件不能证明新增。证据仍不足就写“未知”，注明缺什么。不得 update、reinstall、停止服务或调用账户业务来补证据。

## 3. 按真实差异逐项说明

每个受范围覆盖的 Skill/插件都要有落点；聚合包可先汇总再展开入口。分类使用：

- 功能/入口新增或删除：指出此前入口是否存在、现在如何调用。
- 行为变化：同样输入或工作流现在会怎样，影响何种用户场景。
- 修复：此前问题、修后行为及已有验证边界。
- 文档、metadata、版本号或格式变化：明确是否足以证明业务行为变化。
- 同版本 refresh：文件一致时写“刷新完成，内容无变”；文件不同则继续分类，不能因版本相同就断言无变化。
- 未更新、跳过、失败或未知：各自保留原因，不能算成功变化。

每项给出“旧版是什么 → 新版是什么”“对用户的影响/用法”和支持该结论的旧新路径及行号或固定提交链接。以内容对应，不按编号或文件名硬配；新增/删除独立列出。不要把目录替换、版本升级、新版功能清单自动解释为功能新增，也不从 Skill 可发现推断其模型、账户或外部业务已验收。

## 4. 交付

聊天先给精简摘要：本批范围、主要实际变化、无变化与失败/未知项、证据限制；附完整逐项报告链接。完整报告写在当前任务既有产物目录（没有则采用 workspace 的私有运行数据目录），不要写进插件源码、安装目录或公开仓库。报告保留批次来源、旧新对照、包/入口分开的计数、每项分类、用户影响/用法、可查的 source 路径和行号、未验证业务及缺失证据。链接使用可打开的绝对路径，固定线上来源用提交链接。历史示例仅参考表达方式，不复用其路径、数量或结论。

允许报告“已比较”“已安装/刷新”“业务未验证”同时存在；只读整理完成不等于重新更新或业务验收完成。
